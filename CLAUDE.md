# Навчальний сайт з інформатики (6–11 класи)

- Сайт лежить у `/docs` і публікується GitHub Pages (гілка `main`, папка `/docs`) штатним Jekyll. `baseurl: /python-tkinter-examples`.
- Аудиторія — учні 6–11 класів, часто з телефонів. Увесь видимий текст українською.
- Поточна робота — редизайн за планом @REDESIGN_PLAN.md. Виконуй по одній фазі, після кожної зупиняйся і звітуй.

## Правила

- Не змінюй і не видаляй наявні адреси сторінок і файлів.
- Не вигадуй навчальний вміст: завдання, розв'язки, посилання на підручники. Якщо даних бракує — `TODO` і питання у звіті.
- Лише плагіни з білого списку GitHub Pages, сумісні з Jekyll 3.x. Без npm, збирачів і фреймворків: чиста CSS і мінімальний vanilla JS. Сайт працює без JS.
- Службові файли (план, `design/`, `scripts/`) — поза `/docs`.
- Посилання в шаблонах — лише через `relative_url`.

## Shell і інструменти

- Claude стартує в корені репозиторію. Не роби `cd` у корінь чи за абсолютним шляхом; користуйся відносними шляхами від кореня (`docs/_layouts/...`, `scripts/validate_data.py`).
- Для пошуку й читання віддавай перевагу вбудованим Grep, Glob і Read, а не `grep`, `ls`, `cat` у Bash.
- Якщо `cd` справді неминучий — лише у підпапку за відносним шляхом (наприклад, `docs/` для `bundle exec jekyll build`).
- Команди в Bash — прості: одна команда на виклик. Без ланцюжків через `;`, довгих пайпів і `2>/dev/null`, якщо це не потрібно.

## Перевірки перед комітом

- `cd docs && bundle exec jekyll build` — без помилок і попереджень Liquid.
- `python3 scripts/validate_data.py` — після появи даних (фаза 2).
- Перегляд змінених сторінок на ширині 360 і 1440 px.
- Після змін у `docs/html/project/templates/` чи `example-cafe/` — `scripts/build_project_assets.sh` (перезбирає zip і скріншоти).
