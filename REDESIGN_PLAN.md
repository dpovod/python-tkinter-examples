## 1. Контекст

**Хто і для кого.** Вчитель інформатики веде 6, 7, 8, 9 (пілотний НУШ), 10 і 11 класи. Сайт — довідник для учнів: приклади коду, завдання, матеріали. Учні часто відкривають його з телефона, інколи зі слабким інтернетом.

**Репозиторій і хостинг.**

- Репозиторій: `github.com/dpovod/python-tkinter-examples`, гілка `main`.
- Сайт публікується через GitHub Pages із папки `/docs`: `https://dpovod.github.io/python-tkinter-examples/`.
- Файлу `.nojekyll` немає, тобто GitHub Pages вже пропускає `/docs` через Jekyll. Сторінки без front matter копіюються як є.

**Поточний вміст `/docs`** (усі сторінки — ручний HTML, кожна дублює `<head>` і футер «На головну», спільний `styles.css`):

## 2. Обмеження (не порушувати)

1. **Не змінювати й не видаляти наявні адреси.** Усі поточні `.html` і PDF мають відкриватися за тими самими URL. Сторінки мігрують на шаблони на своїх місцях. Нові сторінки — нові адреси.
2. **Не вигадувати навчальний вміст.** Не писати нових завдань, розв'язків, пояснень і не підставляти посилань на підручники без підтвердження вчителя. Допустимо: виправити очевидні одруки й нумерацію (перелік у розділі 7), перенести наявний текст у новий шаблон.
3. **Обмеження GitHub Pages.** Збірка штатним Jekyll від GitHub Pages (гілка Jekyll 3.x — звір актуальну версію на `pages.github.com/versions`). Лише плагіни з білого списку GitHub Pages. Не використовувати фільтри, яких немає в Jekyll 3 (наприклад, `find`, `find_exp`). Жодних кастомних плагінів-генераторів, npm, збирачів, GitHub Actions для збірки.
4. **Технології фронтенду.** Чиста CSS (можна CSS custom properties) і мінімальний vanilla JS. Без фреймворків і сторонніх JS-бібліотек. Сайт має повністю працювати без JS (JS лише покращує).
5. **Службові файли поза `/docs`.** План, файли дизайну, скрипти перевірки лежать у корені репозиторію, щоб не публікуватися.
6. **Мова.** Увесь видимий текст — українською. Атрибут `lang="uk"`.
7. **Великі файли.** Не комітити файли понад 5 МБ; зображення оптимізувати.

Розділи з `planned: true` не мають уроків і показуються як картки «Розділ готується» (див. 4.4).

**`_data/lessons.yml`** — каталог наявних сторінок. Порядок у межах `subject` = порядок у картці й у навігації «попередня/наступна».

Поля: `id` (унікальний), `title`, `url` (шлях від кореня сайту без baseurl), `subject`, `grades` (класи, де матеріал використовується за КТП), `extra` (підмножина `grades`, де матеріал «Додатково»; в інших класах — «База»).

Стартовий вміст наведено в **Додатку А**. Позначки класів узгоджені з КТП, але вчитель може їх уточнити.

**`_data/ktp/gradeN.yml`** — структура курсу для сторінки класу. Порядок груп = порядок у КТП.

```yaml
grade: 9
title: "9 клас"
hours: "52 уроки"
note: "Пілотний клас НУШ. Модулі побудовано навколо проєктів «Професія: …»."
textbook: textbook-9          # id з resources.yml
groups:
  - title: "Професія: аналітик/еня даних"
    lessons_range: "Уроки 3–7"
    topics: ["Управління даними. Відкриті дані. Тренди", "…"]
    lessons: [excel-filter]   # id з lessons.yml
    resources: []             # id з resources.yml
```

Для 6, 7, 8, 11 замість `lessons_range` використовується `semester: 1` або `2`. Для 10 класу — `semesters: {"10-А": 2, "10-Б": 1}`, бо порядок тем у паралелях різний. Повні скелети для всіх класів — у **Додатку Б**.

**`_data/resources.yml`** — зовнішні посилання, підручники й файли.

```yaml
- id: phishing-quiz
  title: "Phishing Quiz від Google"
  type: link                # book | file | link
  group: security           # textbooks | security | practice | files
  url: "https://phishingquiz.withgoogle.com?hl=uk"
  note: "Англійською. 8 листів із поясненнями після кожної відповіді."
  grades: [6, 7, 8, 9]
  featured: true            # показувати в блоці «Додаткові матеріали» на головній
```

Стартовий вміст — у **Додатку В**. Записи з `url: TODO` на сайті не показуються (фільтрувати в шаблоні) і перелічуються у звіті.

### 3.4. Правила відображення

- **Рівень для конкретного класу:** `Додатково`, якщо `lesson.extra contains grade`, інакше `База`.
- **Рівень у режимі «За темами»** (без обраного класу): бейдж `База`, якщо матеріал є базовим хоча б для одного класу; інакше `Додатково`.
- **Діапазон класів** (`grade-range.html`): послідовні класи зливаються через коротке тире, окремі групи — через кому. `[7, 8, 9]` → «7–9 кл.», `[9, 11]` → «9, 11 кл.», `[8]` → «8 кл.».
- **Попередня/наступна тема** на сторінці уроку: сусіди в `lessons.yml` у межах того самого `subject`. На краях — показувати лише наявну кнопку.
- **Сторінка класу** бере уроки лише з `ktp/gradeN.yml` (не фільтрує каталог автоматично), щоб порядок відповідав КТП.

Орієнтир для Liquid (Jekyll 3):

```liquid
{% assign lesson = site.data.lessons | where: "id", page.lesson | first %}
{% assign siblings = site.data.lessons | where: "subject", lesson.subject %}
{% for l in siblings %}{% if l.id == lesson.id %}{% assign idx = forloop.index0 %}{% endif %}{% endfor %}
{% assign prev_idx = idx | minus: 1 %}
{% assign next_idx = idx | plus: 1 %}
{% if idx > 0 %}{% assign prev = siblings[prev_idx] %}{% endif %}
{% assign next = siblings[next_idx] %}

{% comment %} на сторінці класу (page.grade задано у front matter) {% endcomment %}
{% if lesson.extra contains page.grade %}Додатково{% else %}База{% endif %}
```

Перевір, що порівняння цілих чисел (`grades`, `page.grade`) працює у збірці; якщо ні — перейди на рядкові значення послідовно в усіх файлах.

### 4.3. Типографіка

- **Основний текст:** Manrope (400, 500, 600, 700, 800), Google Fonts, `display=swap`.
- **Заголовки:** у макеті Baloo 2, але цей шрифт **не має кирилиці** — українські заголовки впадуть у системний шрифт. Заміна: **Nunito** (700, 800) як найближчий за характером заокруглений шрифт із кирилицею. Fallback: `system-ui, sans-serif`. Після підключення перевір у DevTools (Computed → Rendered Fonts), що кириличні заголовки справді рендеряться Nunito. Назву шрифту винести в токен `--font-heading`, щоб вчитель міг змінити (альтернативи: Rubik, Comfortaa).
- **Моноширинний:** `'SFMono-Regular', Menlo, Consolas, monospace`, 15 px / 1.7 у блоках коду.
- **Шкала (десктоп → мобільний):** hero h1 50 → 32 px, 800, line-height 1.12; h1 сторінки 42 → 30 px, 800; h2 картки 22 px, 700; h3 завдання 20 → 18 px, 700; основний текст 15–17 px, line-height 1.55–1.6; підзаголовок hero 19 → 17 px.
- **Мінімальний розмір тексту — 12 px** (у макеті діапазон класів 10 px — збільшити).
- Довжина рядка основного тексту — до ~75 символів (`max-width` на абзацах).

- Контейнер: `max-width: 1312px` (3 картки по 416 px + 2 проміжки по 32 px, як у макеті), центрування, бічні відступи 64 px на широких екранах.

- Точки перелому: ≤ 640 px — одна колонка, бічні відступи 16 px, padding карток 20–24 px, hero padding 28/24, перемикач на всю ширину, чипи класів горизонтально прокручуються; 641–1024 px — дві колонки; ≥ 1025 px — три.

### 4.6. Обов'язкові відхилення від макета

Макет — візуальна основа, але його дані й кілька рішень треба змінити:

1. **6 клас** додається до чипів класів (у макеті лише 7–11).
2. **Позначки класів і рівнів** беруться з `_data` за КТП, а не з макета. Рівень залежить від класу.
3. **Excel** — не один рядок, а чотири окремі уроки (формули, посилання, діаграми, фільтри), бо вони належать різним класам. Word — один урок.
4. **Назви розділів:** «SQL» → «Бази даних», «HTML» → «Веб». Tkinter лишається окремим розділом.
5. **Заглушка «Плануються нові розділи»** (JavaScript, ООП) замінюється картками запланованих розділів із `subjects.yml`.
6. **Режим «За класами»** доповнюється кнопкою переходу на сторінку класу; вибраний клас відображається в адресі (`#grade-9`), щоб посилання можна було передати учням, і запам'ятовується в `localStorage`.
7. **Нові сторінки** (клас, ресурси, 404) — у тій самій візуальній мові.
8. **Шрифт заголовків** — Nunito замість Baloo 2 (4.3).
9. **Контраст** — затемнені кольори з 4.2.
10. **«Показати відповідь»** — лише для завдань із розв'язком (4.4).
11. **Підручники** в «Додаткових матеріалах» — зовнішні посилання, а не PDF-файли на сайті.
12. **Підзаголовок hero** у макеті перелічує лише технології. Тимчасовий текст: «Приклади коду, завдання та матеріали з інформатики для 6–11 класів». TODO: підтвердити у вчителя разом із назвою «КОД.УРОКИ».

### 4.7. Доступність (мінімум)

- Контраст тексту ≥ 4,5:1 (великий текст ≥ 3:1).
- Видимий фокус для всіх інтерактивних елементів (`:focus-visible`, контур 3 px кольору `--text` з відступом 2 px).
- Перемикачі — справжні `<button>`/`<a>`, не `div`.
- `prefers-reduced-motion`: без анімацій переходів.
- У кожного зображення змістовний `alt` українською (для скріншотів Excel: що саме зображено в таблиці).

Порядок узгоджено з календарем навчального року. Для кожного пункту агент може підготувати лише **структуру сторінки й чернетку**, яку вчитель перегляне:

1. Кібербезпека й медіаграмотність (6–10): фішинг, паролі й двофакторна автентифікація, фейки й діпфейки, тренажери.
2. Excel: умовне форматування, підсумки, статистика й тренди (9, 10).
3. Бази даних: таблиці, ключі, зв'язки, запити в конструкторі (9, 10, 11).
4. Tkinter: написи й кнопки, прапорець, перемикач, шкала, обробка подій, проста гра (9, 11).
5. Веб: перша сторінка HTML (9), CSS і динамічні елементи (10).
6. Python: сортування, функції з параметрами (8, 11).
7. Графіка й мультимедіа: растрова (8), 3D і доповнена реальність (9), векторна (11).
8. 6 клас: презентації, умови ігрових проєктів №1–5.

## 6. Відкриті питання до вчителя

Постав їх у звіті тієї фази, де вони стають блокерами:

1. Назва сайту «КОД.УРОКИ» і підзаголовок hero — остаточні? (фаза 3)
2. Шрифт заголовків: Nunito чи інший із кирилицею? (фаза 1)
3. Підручники для кожного класу: автори й посилання на бібліотеку ІМЗО. Відомо лише для 9 класу: Н. Морзе, О. Барна, «Інформатика-9». (фаза 4)
4. У якому середовищі 6 клас виконує ігрові проєкти? (беклог)
5. Чи використовується `canvas.html` у 7 класі (урок 30 «Створення графічних примітивів»)? Якщо так — додати 7 до `grades`. (фаза 2)
6. Чи показувати учням розв'язки завдань? (фаза 5)
7. Файли КТП мають позначку 2025/2026 навчального року. Чи актуальні теми на поточний рік? (фаза 2)
8. Позначки класів і рівнів у Додатку А — підтвердити або уточнити. (фаза 2)

## 7. Відомі дрібні дефекти (виправити у фазі 1)

1. `excel/filter.html`: `<title>` «Діаграми в Excel» → «Автоматичні фільтри в Excel».
2. `canvas.html`: одрук у заголовку «за домогою» → «за допомогою».
3. `debug.html`: нумерація завдань повторюється (4, 4, …, 7, 8, 7, 8). Перенумерувати послідовно; якщо завдання 7 і 8 дублюються дослівно — не видаляти, а зазначити у звіті.
4. `line.html`: `<title>` «Слідування» → узгодити з назвою в каталозі («Лінійні алгоритми»).

Помилки в самих документах КТП (не на сайті) — повідомити вчителю у звіті фази 2, не виправляти: в КТП 11-Б «Тема 4» названа «Системи керування базами даних», хоча уроки про векторну графіку; одрук «Занити з функціями та з полями, шо обчислюються».
